# РСХБ · «Путь к своему дому» — цифровая платформа

Full-stack решение трёх кейсов стипендиальной программы РСХБ 2026–2027 (направление «Информационные технологии», продукт «Своё Жильё») в одном приложении:

| Кейс | Модуль | Что внутри |
|---|---|---|
| **Задача 1** | Симулятор «Что, если…?» | 6 финансовых сценариев: ипотека, досрочное погашение, кредит на ремонт, сдача в аренду, строительство дома, сельская ипотека. Платёж, срок, переплата, бюджет — пересчитываются мгновенно |
| **Задача 2** | Навигатор «Путь к своему дому» | 7 адаптивных маршрутов: квартира, дом, участок, строительство, ремонт, сельская ипотека, готовый объект. 42 шага, 238 пунктов чек-листов, прогресс сохраняется |
| **Задача 3** | «Жизнь после ипотеки» | 10 сервисов после оформления: досрочное погашение, налоговый вычет, справки, страхование и др. Гость видит демо-данные, авторизованный — свой банковский контур |

## Стек

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy (ORM), SQLite (разработка) / PostgreSQL (продакшен)
- **Frontend:** чистый HTML/CSS/JS — без сборки и npm-зависимостей
- **Инфраструктура:** Docker + docker-compose (backend + PostgreSQL + миграции при старте)

## Быстрый старт (для не-программиста) — 3 команды

Нужен только установленный [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/Mac) или Docker Engine (Linux).

```bash
git clone https://github.com/ВАШ_ЛОГИН/rshb-dom-platform.git
cd rshb-dom-platform
docker compose up --build
```

Откройте **http://localhost:8078** — готово. Демо-логин: **demo / demo**.

Первый запуск скачивает образы и собирает контейнеры (2–5 минут). Останов: `Ctrl+C` или `docker compose down`.

## Что посмотреть после запуска

1. **Вкладка «Симулятор»** — выберите сценарий (например «Досрочное погашение»), покрутите ползунок суммы взноса: платёж/срок/переплата пересчитываются, экономия подсвечивается
2. **Вкладка «Навигатор»** — выберите «Участок»: маршрут меняется, появляются межевание и ВРИ; кнопка «Сравнить сценарии» показывает таблицу различий
3. **Вкладка «Жизнь после ипотеки»** — сначала гость (демо-кредит), затем войдите demo/demo: карточка подтянет данные из «банковского контура» (БД)
4. **Вкладка «Кабинет»** (появляется после входа) — всё, что вы сделали, в одном месте: прогресс по маршрутам (таск-трекер), черновики расчётов (открыть → параметры восстанавливаются), ипотеки и планы по сервисам. Кнопка «Завершить ✓» на последнем этапе навигатора сохраняет итог маршрута в кабинет
5. **Вкладка «Админ · сценарии»** (видна только после входа администратором) — создайте новый сценарий через форму: параметры, формулы, условные подсказки; после сохранения он сразу появляется у всех пользователей

## Роли и доступы (трёхуровневая авторизация)

| Роль | Как войти | Возможности |
|---|---|---|
| **Гость** | без входа, пароль не нужен | Расчёты симулятора, навигатор, демо-данные «Жизни после ипотеки»; история не сохраняется |
| **Пользователь** | demo/demo или регистрация | + личный кабинет (прогресс маршрутов, черновики расчётов, ипотеки, планы), своя история расчётов, свой прогресс чек-листов, свой банковский контур — данные изолированы по аккаунту |
| **Администратор** | admin/admin | + вкладка «Админ · сценарии»: добавление/правка/удаление сценариев, формул, параметров и подсказок без изменения кода |

Текущая роль отображается в правом верхнем углу шапки («Гость», «Пользователь · Иванов Иван», «Администратор · …»). Пароли хранятся как PBKDF2-HMAC-SHA256 с солью (260 000 итераций), сеансы — bearer-токены со сроком жизни 12 часов. Попытка зайти под админом с неверным паролем отклоняется; доступ пользователя к админ-эндпоинтам возвращает 403.

## Дизайн-система фронтенда

Интерфейс построен по профессиональным практикам веб-дизайна (двухуровневые дизайн-токены, mobile-first, доступность WCAG AA):

- **Дизайн-токены (2 уровня).** Примитивы (`--g-50…--g-900`, `--n-0…--n-900`, `--sp-1…--sp-8`) → семантические токены (`--color-primary`, `--color-surface`, `--fs-base`…). В компонентах используются только семантические токены — тема меняется в одном месте
- **Цвет.** Фирменный зелёный РСХБ `#1E9E4A` + правило 60-30-10 (60% фон, 30% поверхности, 10% оранжевый акцент только для подсказок). Все текстовые сочетания проходят WCAG AA ≥ 4.5:1
- **Типографика.** Одна семья (Inter/system-ui), шкала major third 1.25 с `clamp()` — плавное масштабирование без media-queries, тело ≥ 16px
- **Сетка.** 8px baseline, контейнер 1200px, сетки 1→2→3 колонки от мобилы к десктопу (mobile-first, `min-width`)
- **Доступность.** Клавиатурная навигация (карточки — `role="button"` + Enter/Space), видимый `:focus-visible`, `aria-selected` у вкладок, закрытие модалки по Esc, touch-targets ≥ 44px, `prefers-reduced-motion`
- **Состояния.** У кнопок и полей определены default/hover/focus/active/disabled; 3 уровня теней в одном направлении

## Архитектура

```
┌──────────────────────────────────────────────────┐
│ Браузер: frontend/index.html (SPA без сборки)    │
└────────────────────┬─────────────────────────────┘
                     │ REST/JSON
┌────────────────────▼─────────────────────────────┐
│ FastAPI (backend/app)                            │
│  ├─ routers/sim.py   — сценарии + расчёты + CRUD │
│  ├─ routers/nav.py   — маршруты + прогресс       │
│  ├─ routers/life.py  — сервисы + вход + контуры  │
│  ├─ finance.py       — safe_eval: формулы админа  │
│  │                      исполняются через AST,    │
│  │                      без eval()               │
│  └─ models.py        — SQLAlchemy ORM            │
└──────┬───────────────────────────────┬───────────┘
       │                               │
  SQLite (dev)                  PostgreSQL (Docker)
```

**Ключевое решение (Задача 1, требование «настройка администратором»):** формулы хранятся в БД как строки и исполняются изолированным интерпретатором `safe_eval` на основе AST-анализа Python — доступны только арифметика, сравнения, тернарники и белый список функций (`annuity`, `months_to_repay`, `min/max/…`). Никакого `eval()`, доступа к файлам или импортам — сценарий невозможно превратить во вредоносный код. Администратор создаёт сценарий POST-запросом: параметры, формулы и подсказки описываются JSON'ом, расчёт подхватывается сразу.

## API (полная документация — /docs, Swagger UI генерируется автоматически)

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/health | Проверка живости |
| GET | /api/auth/me | Текущая роль по токену (guest/user/admin) |
| POST | /api/auth/login | Вход (demo/demo — Пользователь, admin/admin — Администратор) |
| POST | /api/auth/register | Регистрация (всегда роль «Пользователь») |
| POST | /api/auth/logout | Отзыв токена |
| GET | /api/sim/scenarios | Список сценариев симулятора |
| POST | /api/sim/calc | Расчёт сценария (гостю доступен, история — только пользователю) |
| GET | /api/sim/history | Своя история расчётов (только авторизованный) |
| POST/PUT/DELETE | /api/sim/admin/scenarios | Только Администратор: создать/изменить/удалить сценарий |
| GET | /api/nav/scenarios/{key} | Маршрут навигатора |
| POST | /api/nav/progress | Отметка пункта чек-листа (прогресс изолирован по роли) |
| GET | /api/life/services | Каталог сервисов «после ипотеки» |
| GET | /api/life/context | Гость → демо-данные; токен → банковский контур |
