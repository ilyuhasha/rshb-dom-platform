# Техническая документация
## Платформа «РСХБ · Путь к своему дому» v1.0.0

Документ описывает архитектуру, модель данных, вычислительное ядро, API, развёртывание и тестирование платформы. Рассчитан на разработчика, DevOps-инженера и ревьюера технического решения.

---

## 1. Обзор системы

Платформа объединяет три продуктовых модуля кейса «Своё Жильё» в едином full-stack приложении:

| Модуль | Кейс | Ключевая функциональность |
|---|---|---|
| Симулятор «Что, если…?» | Задача 1 | 6 финансовых сценариев; вычислительное ядро на основе формул, редактируемых администратором без деплоя |
| Навигатор «Путь к своему дому» | Задача 2 | 7 адаптивных маршрутов клиента; серверное хранение прогресса |
| «Жизнь после ипотеки» | Задача 3 | 10 пост-ипотечных сервисов; два контура данных: демо (гость) и банковский (авторизованный) |

### 1.1 Нефункциональные требования и их реализация

| Требование | Реализация |
|---|---|
| Изолированность расчётов | Формулы исполняются AST-интерпретатором с белым списком узлов и функций; отдельные сценарии не имеют общего состояния |
| Настраиваемость администратором | Сценарии/формулы/параметры/подсказки — данные в БД, управляются REST CRUD без пересборки |
| Работа на публичном сайте и в ЛК | Единый SPA; контент гостя (демо) и ЛК (токен) различаются на уровне API-контекста |
| Простота развёртывания | docker compose up — единственная точка входа; схема БД и сиды применяются автоматически при старте |

## 2. Архитектура

```
Клиент (браузер)
   │  frontend/index.html — SPA без этапа сборки
   │  Табы: Симулятор | Навигатор | Жизнь после ипотеки
   ▼
FastAPI (ASGI, uvicorn)
   │
   ├─ /api/sim/*   routers/sim.py      — сценарии, расчёты, админ-CRUD
   ├─ /api/nav/*   routers/nav.py      — маршруты, прогресс, админ-CRUD
   └─ /api/life/*  routers/life.py     — сервисы, авторизация, контуры
        │
        ├─ finance.py  — safe_eval (AST) + финансовые функции
        ├─ models.py   — SQLAlchemy 2.0 ORM (7 таблиц)
        └─ init_db.py  — create_all + идемпотентные сиды
                 │
        ┌────────┴────────┐
   SQLite (dev)      PostgreSQL 15 (docker compose)
```

### 2.1 Слои и принципы

- **Слой представления** — один HTML-файл (~28 КБ): рендеринг карточек, форм и таблиц на чистом JS; состояние вкладок в памяти, токен — в localStorage.
- **Слой API** — три роутера по доменам; Pydantic-валидация входа; JSON-ответы; Swagger на `/docs` генерируется из кода.
- **Слой домена** — `finance.py`: чистые функции без состояния, пригодны для прямого юнит-тестирования и переиспользования.
- **Слой данных** — ORM-модели; JSON-поля для схем параметров/формул (гибкость админ-настройки против жёсткой реляционной схемы — осознанный компромисс: схема сценариев — это контент, а не структура).

### 2.2 Потоки данных (примеры)

**Расчёт сценария:** клиент → POST /api/sim/calc → загрузка сценария из БД → слияние input с дефолтами схемы → последовательное вычисление формул (результат каждой доступен следующим как переменная) → фильтрация подсказок по условиям → запись в SimCalculation (история) → JSON.

**Банковский контур:** гость → GET /api/life/context без заголовка → source=demo + захардкоженный демо-объект; клиент с токеном → сопоставление токена (in-memory store) → ипотеки пользователя из БД → source=bank. В продакшене in-memory store заменяется Redis/БД с TTL, а токен выпускается существующим IAM банка — интерфейс `current_user()` для этого изолирован.

## 3. Вычислительное ядро (Задача 1)

### 3.1 Финансовые формулы

Ядро оперирует аннуитетной моделью:

```
платёж:  P = S · i·(1+i)^n / ((1+i)^n − 1),   i = rate/12/100
срок:    n = ln(P/(P − S·i)) / ln(1+i)          (обратная задача)
переплата: Ov = P·n − S
```

Дополнительные функции: `total_paid`, `overpay`, `reduce_term_effect`, `reduce_payment_effect`, `rental_income` (простой × управление × НПД 4%), `tax_deduction` (вычеты 13% с лимитами 2/3 млн ₽), `budget_available`, `annual_share`.

Граничные случаи: нулевая ставка → деление без процентов; платёж ≤ процентам → маркерный срок 7200 мес. («не гасится») вместо `inf` (JSON-сериализуемость); ZeroDivisionError → 0.0.

### 3.2 safe_eval — исполнение формул администратора

Формулы хранятся строками в БД. Исполнение — собственный интерпретатор по AST дерева Python (`ast.parse` → рекурсивный обход с белым списком):

- **Разрешены:** числовые литералы, `+ − * / // % **`, унарные минус/плюс/not, сравнения, тернарный `x if c else y`, вызовы белого списка функций, переменные.
- **Запрещены (узлы просто не обрабатываются):** атрибуты (`__class__`, `os.system`), подписчики, лямбды, импорты, f-строки, присваивания.
- **Синтаксический сахар:** `if(cond, a, b)` переписывается в тернарник перед парсингом — привычная форма для банковских аналитиков.
- **Функции в формулах:** `annuity`, `months_to_repay` передаются через словарь переменных; попытка вызвать что-либо иное — `ValueError`.

Ошибка одной формулы не рушит расчёт: строка возвращается с `error`, остальные вычисляются.

### 3.3 Встроенные сценарии

| Ключ | Сценарий | Формулы (выборка) |
|---|---|---|
| mortgage_base | Базовая ипотека | loan, payment, total, overpay, overpay_pct, dti |
| prepay | Досрочное погашение | months_before/after, saved_interest, months_saved |
| repair_loan | Кредит на ремонт | repair_payment, total_payment, dti, budget_left |
| rent_out | Сдача в аренду | effective_rent, cashflow, payback_years, yield_pct |
| build_house | Строительство | total_project, tranche, build_interest, debt_after_build, payment_after, dti |
| rural_mortgage | Сельская ипотека | payment_rural vs payment_market, month_saved, total_saved |

Подсказки сценариев поддерживают `condition` — произвольное безопасное выражение от переменных расчёта (например, показывать предупреждение при ДТІ > 50%).

## 4. Модель данных

7 таблиц SQLAlchemy:

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| users | Пользователи | username, password_hash (PBKDF2-SHA256+salt), is_admin |
| mortgages | Ипотеки («банковский контур») | user_id →, principal, rate, term_months, monthly_payment, remaining_debt, insurance_end |
| sim_scenarios | Сценарии симулятора | key (uniq), params_schema (JSON), formulas (JSON), hints (JSON), is_builtin |
| sim_calculations | История расчётов | scenario_key, inputs, results (JSON), created_at |
| nav_scenarios | Маршруты навигатора | key (uniq), steps (JSON: [{stage, key, title, summary, checklist[], tips[]}]), color |
| nav_progress | Прогресс чек-листов | user_id →, scenario_key, step_key, item_index, done |
| life_services | Сервисы «после ипотеки» | key (uniq), how_to, docs, hints, calculator (JSON), requires_auth |
| life_actions | Действия пользователя | user_id →, service_key, status, payload |

Сидирование идемпотентно: при старте таблицы создаются, встроенные записи вставляются `ON CONFLICT DO NOTHING`-паттерном (проверка существования по ключу), поэтому рестарт контейнера не дублирует данные и не затирает админ-правки.

## 5. API-спецификация

Полная интерактивная спецификация: `GET /docs` (Swagger UI) и `GET /openapi.json`.

### 5.1 Симулятор (/api/sim)

| Метод | Путь | Тело/параметры | Ответ |
|---|---|---|---|
| GET | /scenarios | — | [{key, title, category, icon, params_schema, hints_count}] |
| GET | /scenarios/{key} | — | сценарий целиком (params_schema, formulas, hints) |
| POST | /calc | {scenario_key, inputs{}} | {results: [{key,label,value,unit,hidden,error?}], hints: [{title,text}], errors} |
| GET | /history?limit= | — | последние расчёты |
| POST | /admin/scenarios | ScenarioIn | 201 {ok, key}; 409 если key занят |
| PUT | /admin/scenarios/{key} | ScenarioIn (частично) | 200 {ok}; изменяются только переданные поля |
| DELETE | /admin/scenarios/{key} | — | 200; 400 для is_builtin |

Коды ошибок расчёта: 404 сценарий не найден; ошибки формул — внутри ответа (results[].error), HTTP остаётся 200.

### 5.2 Навигатор (/api/nav)

| Метод | Путь | Назначение |
|---|---|---|
| GET | /scenarios | Список 7 маршрутов + счётчики шагов/пунктов |
| GET | /scenarios/{key} | Полный маршрут: steps[] с checklist[] и tips[] |
| POST | /progress | {scenario_key, step_key, item_index, done} — upsert |
| GET | /progress/{scenario_key} | [{step_key, item_index, done}] |
| POST | /progress/{scenario_key}/reset | Очистка прогресса |
| POST/PUT | /admin/scenarios | CRUD маршрутов для администратора |

### 5.3 Жизнь после ипотеки (/api/life)

| Метод | Путь | Авторизация | Назначение |
|---|---|---|---|
| GET | /services | — | Каталог 10 сервисов |
| GET | /services/{key} | — | Детальная: how_to, docs, hints, calculator |
| POST | /login | — | {username, password} → {token, user}; демо demo/demo |
| GET | /context | опционально | Гость: source=demo + демо-ипотека; токен: source=bank + ипотеки из БД |
| POST | /actions | Bearer | Запланировать действие {service_key, status, payload} |
| GET | /actions | Bearer | Список действий пользователя |

Ошибки: 401 неверный логин/нет токена, 404 сервис не найден.

## 6. Развёртывание

### 6.1 Docker (рекомендуемый путь)

`docker-compose.yml` поднимает два сервиса:

- **db** — postgres:16-alpine, том `pgdata`, healthcheck `pg_isready`;
- **backend** — образ собирается из `backend/Dockerfile` (python:3.11-slim, копирование зависимостей → `pip install` → код; слои кэшируются), env `DATABASE_URL=postgresql+psycopg2://rshb:rshb_secret@db:5432/rshb`, depends_on с condition: service_healthy, порт хоста 8078 проксируется в 8000 контейнера.

Схема и сиды применяются при старте (startup-хук `init_db()`), поэтому ручных миграций нет. Для продакшена рекомендуется Alembic; точка входа для подключения — `database.py`.

```bash
docker compose up --build      # собрать и запустить
docker compose down            # остановить (данные в томе pgdata сохранятся)
docker compose down -v         # остановить и стереть БД
```

### 6.2 Без Docker (разработка)

`uvicorn app.main:app --port 8078 --app-dir backend` c SQLite — см. README.

### 6.3 Конфигурация

| Переменная | Default | Назначение |
|---|---|---|
| DATABASE_URL | sqlite:///rshb.db | Подключение БД (psycopg2 для PG) |
| APP_NAME / APP_VERSION | РСХБ · Путь к своему дому / 1.0.0 | Метаданные /api/health |

Секретов в репозитории нет; пароли в БД — только хэши PBKDF2-SHA256 с солью.

## 8. Ограничения и план развития

Текущая версия — конкурсное демо с продакшен-каркасом. Намечено:

- JWT + refresh в Redis вместо in-memory токенов; rate-limiting на /login
- Alembic-миграции; админ-панель с UI (сейчас CRUD через /docs)
- График остатка долга и amortization-schedule в симуляторе
- Экспорт расчёта в PDF; печать чек-листа навигатора
- CI (GitHub Actions): линт, тесты, сборка образа
- Кэширование сценариев (сейчас каждый расчёт читает БД — при масштабе вынести в LRU)
